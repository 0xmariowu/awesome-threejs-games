# Monolith Wilds terrain streaming

Fly over the original procedural landscape while its quadtree selects terrain
chunks, dispatches worker jobs, installs geometry and refines detail around the
camera. The small map shows visible chunk footprints in white and pending worker
jobs in orange. Its center follows the camera; the arrow shows the viewing direction.

```sh
node tools/server.mjs examples/monolith-terrain
# http://127.0.0.1:8123/
node --test examples/monolith-terrain/*.test.mjs
python3 examples/monolith-terrain/test_browser.py
```

No build or package installation is needed. The host uses browser ES modules and
the archived Three.js runtime. It fits the library's 16:9 iframe.

## Controls

Use WASD to fly, drag to look, Space/Q to rise/sink, Shift to boost and the wheel
to change speed. Clicking the canvas requests the original pointer lock; Escape
releases it. The original F key still switches between walking and flying.
The host starts in flight at 180 m/s using the original speed setter.

The three Chinese buttons toggle the original material's wireframe, delay chunk
job dispatch by 250 ms, and return to the starting view. Delayed jobs still run in
the original workers and return their original transferable buffers.

## Extraction boundary

Every file in `original/` is a byte-for-byte copy from `monolith-wilds/assets/`.
`provenance.json` pins both archive paths and SHA-256 hashes. The provenance tests
rehash the copies and archive files, including the two candidate source hashes.

- `terrain-MmovLCQt.js`: original worker pool, quadtree selection, eviction,
  geometry allocator, material, morph heights and normals; exports `build()`.
- `terrain-worker-DVcr_hr3.js`: self-contained original height/map/chunk worker.
- `index-DGqtqlWq.js`: original height/noise/layout exports, scene environment,
  renderer and bootstrap. Its existing `modules=terrain,controls&skip=post`
  whitelist restricts startup to this technique and its controls. The host sets
  these launch parameters before import and restores its address afterward.
- `biome-DstsBN7N.js`: original biome queries used by terrain shading.
- `controls-DX7CeMlr.js` and `obstacles-DQBr1hBF.js`: original input, flight and
  terrain-clearance behavior.
- `three.core-DtjtRha-.js` and `three.module-e53_FFk2.js`: matching original engine.

The entry module's boot side effect is configured through its existing options;
no source text is rewritten, sliced, evaluated or replaced with a host height
function. Its unrelated dynamic imports remain dormant and are not copied.
The landscape and material textures are generated by the original code, so no
external models or textures are needed.

`src/host.js` provides the new Chinese panel, starting pose, worker observation
and chunk map. The map reads the original batched meshes through Three.js bounds
and visibility APIs. `window.__example.state` exposes snapshots of camera pose,
visible tiles, terrain statistics, real worker counts and errors for tests.

## Verification and limits

The browser test starts and stops its own server on port 8123 and uses installed
Chrome headlessly. It checks direct and iframe flight, keyboard movement, mouse
look, worker completions after movement, changed visible tiles, pending-job
drain, wireframe, delayed dispatch and return to the start. Console/page errors,
failed requests and zero executed tests fail the run. Screenshots are written to
`screenshots/` and were visually inspected during development.

This is one terrain technique, with the original environment lighting but no sky
mesh, water, landmarks, vegetation, audio, HUD or postprocessing. The standalone
worker contains its own original height function, so this example does not claim
an injectable arbitrary-height API. Main-thread startup work remains as in the
original; worker counters count worker messages only. Tests require actual worker
use rather than accepting the original main-thread fallback. Long-route memory
bounds, all LOD seams, touch and gamepads are not certified. Maturity remains
`extracted-unverified`.
