## Hanakawa 为什么停在加载页

普通 Chrome 中，本地页面打开约 80 秒后仍显示“Lighting the lanterns”。观察到最长 11.925 秒的主线程任务。214 个文件与原站一致，加载期间没有发现缺失资源；这不是可以用“网页返回 200”带过的问题。

原版启动流程会等待画面刷新。浏览器把标签页判为后台后，刷新暂停，加载也可能停住。原站放在后台 75 秒同样没有完成加载，刷新次数为 0。本地后续运行在约 91 秒达到就绪，但期间前后台状态变化，因此这不是受控的前台加载耗时。

另一轮独立 Chrome 测试中，本地可以进入河道、离泊并移动，原游戏统计为 60 fps。此前的后台暂停已复现，但首次长卡顿尚未完全归因；没有清空图形缓存，后续较快的结果不能证明问题已经修好。原版启动和渲染代码均未修改。

诊断记录、卡住时的页面、本地最终加载画面和原站后台状态保存在仓库之外的本地证据中。

## Moritsuki 黑屏范围

蛤蜊小游戏已进一步隔离到 WaterPass（水面画面处理）或它的输入：直接绘制原场景可以看见沙地和工具，临时停用水面处理后也能看见；仅停用光晕处理仍然全黑。因此不能把它解释成没有抓到场景模型。具体图形计算或驱动原因尚未确认。

这些开关只用于一次性的诊断页面，没有写入归档代码。去掉水面不符合原版效果，不能作为“修复完成”。这组对比保存在仓库之外的本地诊断截图和记录中。

## 已修复的问题

- **Monolith 字体漏抓**：补齐原站字体样式表和 8 个字体文件，只改加载地址。断网复测无外部请求、HTTP 错误或页面异常。
- **旧本地服务会崩溃、端口会串用**：Hanakawa 和 Monolith 的旧服务收到异常编码网址会退出；端口被占用时还会自动换到下一端口。已复现并改用共享静态服务，保留原包装文件备份，原游戏文件未改。
- **重复加载缺少缓存校验**：共享服务新增文件校验标记。未变化的资源返回 304，不再重复传输正文；文件改变后会返回新内容。13 个运行入口都已验证。此项不代表首次预热卡顿已经解决。
- **Moritsuki 署名链接失效**：把错误的本地链接恢复成原版国土地理院链接。
- **Vox 文件换行被转换**：17 个文件已恢复原始字节，并修复抓取工具，防止再次改写换行。
- **检查工具漏掉旧目录及新失败结果**：支持旧项目根目录布局，运行检查优先读取最新证据，不再被较早的成功记录盖住。

修改清单和备份路径保存在仓库之外的本地记录中。没有重写游戏玩法、替换美术、伪造服务端响应或降低游戏画质。

## 原始实现与证据边界

Hanakawa 的 214 个文件、Monolith 原有的 40 个文件重新从用户提供的原站下载并逐字节核对。Inkwave 的 70 个原版运行及支持文件与保留的 `origin/main`（`11ce485`）一致；原网页已失效，只能说明和这个基线相同，不能补造原网页的验收结果。

新项目保留可获取的原始部署文件；Sakuragaoka 和 Tidewater 同时保留指定提交的 Git 源码。Everdrift 的 WASM 和 GDC 属于编译产物，不能说成完整开发源码。Claude 项目保留恢复出的游戏模块，移除的只是宿主页面代码。

35 个运行文本文件与抓取原文存在差异，均已记录为资源地址本地化或移除部署平台包装；Vox 的多余换行转换已撤销。先前 12 款的 856 项二进制头部／压缩检查没有发现问题，GLTF 内引用检查也未发现缺文件。新增 Arkenfall 的 88 个文件均与原始下载字节一致，14 张图片可解码，11 个字体头部有效。这些检查不等于对全部游戏内容的完整性证明。

另保留了 1 个不在运行清单中的旧字体 CSS 文件，位于 Moritsuki 的字体目录；未发现运行页面引用，断网测试没有请求它。它没有被算进已校验的 3925 个清单文件，也未擅自删除。

文件校验、本地化差异、原站比较索引和 Moritsuki 画面问题的记录保存在仓库之外。

## 运行与复查

在各项目目录运行 `npm start`。原版 Inkwave 使用 `python3 -m http.server 8088 --bind 127.0.0.1`。端口和入口见[项目目录](README.md)。

```sh
python3 -m unittest discover -s tools -p 'test_*.py'
node --test tools/server.test.mjs
python3 tools/audit.py --all
python3 tools/audit.py --all --runtime
```

14 个 Python 测试及静态服务测试通过；两个旧服务入口的真实进程检查也通过。原 Sakuragaoka 的 `npm run check`、Tidewater 的 `npm test` 已通过。文件校验通过；运行检查保留 Hanakawa 加载问题和 Moritsuki 黑屏失败，不把它们改成绿色。

本报告与[机器可读结果](full-audit.json)一起保存。未覆盖完整通关、全部天气和地图、移动端触屏、所有浏览器，以及缺失后端提供的功能。
